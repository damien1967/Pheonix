I am a building a mobile gaming platform called Pheonix. Pheonix is a game mechanic engine for tile and piece manipulation games on mobile devices.

I have development experience but I am a bit rusty. The last pieces of code i wrote in anger were in swiftUI; I have over the years used pascal, basic, C, C++, objective-C, swift, kotlin (a bit), javascript (a bit) and react native (a bit - and I hated it).

The engine is cross platform I prefer to implement in Kotlin and SwiftUI (Kotlin Multi-Platform)

For details on the engine see pheonix_core_overview.md

The project is for returning developers (including me) to be able to produce repeatable, generic games which have broadly the same philosophy (grid, pieces, finger control and placement of pieces).

I'm interested in quality, to the point that I am interested in a full assurance approach to testing writing new functionality together with building release versions that pass release testing.

I want simple, best practices to be followed as a point of principle. I am not at all interested in fancy algorithms that are hard for me understand. 

I want full test coverage where possible.

I need free to use online tools that are appropriate to my needs and that can be shared with a very small team.
